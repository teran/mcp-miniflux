A stateless **Remote (HTTP)** [Model Context Protocol](https://modelcontextprotocol.io) server that
exposes the [Miniflux](https://miniflux.app) RSS reader API as a set of specific,
strongly-typed MCP tools. It runs as a **sidecar container next to a Miniflux
instance** and lets an MCP-capable model-driven client (an LLM agent) read,
write and manage feed subscriptions, categories and entries through a safe,
least-privilege, secrets-safe tool surface. The Miniflux API token is passed
straight through as the `X-Auth-Token` header — nothing is stored or converted.

> Default language for this repository is **English**. `SPEC.md` and `AGENTS.md`
> are strictly English. If you need the README (or any doc) in another language,
> you must request it explicitly.

## Features

- **Feeds** — `list_feeds`, `get_feed`, `create_feed`, `update_feed`,
  `refresh_feed`, `delete_feed`, plus `discover_subscriptions` (probe a URL for
  candidate feeds before subscribing).
- **Categories** — `list_categories`, `create_category`, `update_category`,
  `refresh_category`, `delete_category`.
- **Entries** — `list_entries`, `get_entry`, `get_feed_entries`,
  `update_entries` (bulk status/starred), `update_entry`,
  `toggle_entry_bookmark` (bookmark for later).
- **Mark-as-read** — `mark_feed_entries_read`, `mark_category_entries_read`.
- **Counters** — `get_counters` (per-feed and total unread/read counts).
- **Current user** — `get_me` (read-only profile).
- **OPML** — `export_opml` / `import_opml` for backup and migration.
- **History cleanup** — `flush_history`.

Tools are **grouped read → write/update → delete**, each strongly typed with its
own `inputSchema`/`outputSchema`, annotations (`readOnlyHint`, `destructiveHint`,
`idempotentHint`) and instructions. Destructive tools (`delete_feed`,
`delete_category`, `flush_history`) are `destructiveHint: true` and require
human confirmation (**human-in-the-loop**).

**Least privilege:** user *management* and *API-key management* are
intentionally **not** exposed (the server operates with a scoped API key and must
not be able to mutate account-level principals or credentials). Only the read-only
`get_me` is available.

Build and run a standalone binary:

```bash

./dist/mcp-miniflux -mode http
```

### Configuration (env vars)

> **Launch mode** is selected by the **`-mode http|stdio` CLI flag** (default
> **`stdio`**), not an env var. The **deployed** mode is **`http`** (set in the
> container `ENTRYPOINT`); `stdio` is only for local debugging. In **`http`**
> mode logging is **always enabled** at **`info`** by default; in **`stdio`**
> mode it is enabled only when `LOG_LEVEL` is set (L02).

| Env var | Type | Default | Description |
|---------|------|---------|-------------|
| `MINIFLUX_API_URL` | `string` | — | Base URL of the Miniflux instance (e.g. `https://reader.example.com`). **Required.** |
| `MINIFLUX_API_TOKEN` | `string` | — | Miniflux API token (`secret:true`). Used for the server's own outbound calls and/or as the fallback when a client supplies no token. |
| `LISTEN_ADDR` | `string` | `:8080` | MCP app (Streamable HTTP) listen address (O04). |
| `INTERNAL_ADDR` | `string` | `:8081` | Internal observability listen address — Prometheus + pprof + probes (O01/O04). |
| `LOG_LEVEL` | `string` | `info` (HTTP) | Log level (`info`, `debug`, …). In stdio mode, unset ⇒ logging disabled. |
| `LOG_FORMAT` | `string` | `text` | `text` (logrus text, full absolute timestamp) or `json`. |
| `LOG_FILENAME` | `string` | — | Log file for `-mode stdio` (chmod 600). Ignored in HTTP mode (logs go to stdout). |
| `ALLOW_DIRS` / `ALLOW_SYMLINKS` | — | N/A | **Not applicable** — this server has **no local filesystem access** (S04 N/A). |

Configuration is loaded with
[`kelseyhightower/envconfig`](https://github.com/kelseyhightower/envconfig).

### Authentication & token resolution

- **Outbound (server → Miniflux):** the server passes the `X-Auth-Token` header
  to the Miniflux API. The token is resolved in this order:
  1. the inbound request's own `X-Auth-Token` header, if present (**true
     pass-through** — the client authenticates itself to Miniflux directly);
  2. otherwise, `MINIFLUX_API_TOKEN` from the environment.
- **Inbound (MCP client → server):** the server authenticates inbound requests by
  requiring the same `X-Auth-Token` header.
- No OAuth2 is used in either direction (Miniflux has no OAuth2-for-API; it uses
  its native API key). No token is stored, rotated, or logged (L05/S02).

## Deployment

The core use case is a **Docker Compose sidecar next to Miniflux**. Add a service
to your Compose stack, wire it to the Miniflux network, pass the internal Miniflux
service URL and the API token, and expose `:8080`.

```yaml
services:
  miniflux:
    image: miniflux/miniflux:latest
    # ... your existing Miniflux config, networks, volumes ...
    networks:
      - miniflux-net

  mcp-miniflux:
    image: ghcr.io/teran/mcp-miniflux:latest   # replace with your registry/image
    restart: unless-stopped
    networks:
      - miniflux-net
    environment:
      MINIFLUX_API_URL: "http://miniflux:8080"  # internal Miniflux service URL
      MINIFLUX_API_TOKEN: "${MINIFLUX_API_TOKEN}" # your Miniflux API key
      LISTEN_ADDR: ":8080"
      INTERNAL_ADDR: ":8081"
      LOG_LEVEL: "info"
      LOG_FORMAT: "text"
    ports:
      - "8080:8080"   # MCP app (Streamable HTTP) — forward only this through the proxy

networks:
  miniflux-net:
    driver: bridge
```

The MCP listener (`:8080`) is what the MCP client / LLM gateway connects to. The
internal observability listener (`:8081`) is **not** meant to be exposed
publicly — keep it on the Docker network (or bind it to `127.0.0.1:8081`).

## Auth & TLS

- **Miniflux API token pass-through** (`X-Auth-Token`), described above.
- **TLS is never implemented in-server** — the server listens on plain HTTP.
  **Terminate TLS at the reverse proxy** (nginx / Caddy / an ingress) in front of
  the HTTP listener (S01/N01). Example nginx hint:

```nginx
server {
    listen 443 ssl;
    server_name mcp.example.com;
    # ssl_certificate / ssl_certificate_key ...

    location / {
        proxy_pass http://mcp-miniflux:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    }
}
```

## Logging & Observability

- **Logging (L01):** HTTP mode logs to **stdout** (12-factor), **always enabled**
  at default **`info`** (L02); `LOG_LEVEL`/`LOG_FORMAT` override it. Stdio mode
  logs to a file and is enabled only when `LOG_LEVEL` is set.
- **Startup banner (B05/L06):** when logging is enabled (always in HTTP mode),
  the **first log line** at startup is
  `Starting {appName}/{appVersion} (commit: {appCommit}; built at {appTimestamp}) ...`.
- **Tool-call access log (L08):** each `tools/call` emits an `info`-level line
  (tool / **redacted** args / source / duration / outcome), visible whenever
  logging is on.
- **No secrets in logs (L05/S02):** `secret:true` fields (feed `password`, the
  API token) are stripped from all tool output and logs by a single redaction
  helper.
- **`request_id` correlation (L09):** a `request_id` is generated per request,
  threaded through every log record, and propagated to the outbound Miniflux call
  as `X-Request-ID`.
- **Observability endpoint (O01/O04), separate listener `:8081`:**
  - `/metrics` — Prometheus (Go runtime + `net/http` request latency/size/status),
    plus **upstream Miniflux response metrics** (upstream latency/size + a
    status-code counter labelled by upstream status) so you can see whether
    Miniflux is reachable/healthy (O03).
  - `/debug/pprof/` — Go pprof profiles.
  - `/healthz`, `/readyz`, `/startupz` — liveness / readiness / startup probes
    (reflect process/listener state only, **not** upstream reachability).

Because observability is on a separate address, a reverse proxy forwards **only**
the MCP app port `:8080`.
